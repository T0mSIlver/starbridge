# What agents parse

Agents, the Starbridge skill, the Claude Code plugins, the Pi extension and the opencode
plugin read the commands below and their output. The plugins update apart from the CLI, so this list is
stable from 0.1.0, the first public release: a release may add commands, flags, variables, fields
and lines, but changes or removes anything here only after a release that deprecates it. `cli/test/contract.test.ts` pins
the lines; the hook outputs are pinned in `cli/test/permissions.test.ts`.

| Command | Contract |
|---|---|
| `ask` | Flags `--question`, `--context`, `--context-file`, `--option`, `--recommended`, `--waiting`, `--agent`, `--project`, `--session`, `--session-title`, `--session-link`, `--image`, `--link`, `--answer-in`, `--input <path>` (a JSON file with the same fields, `-` for stdin), `--wait`, `--timeout`. Prints the decision id alone on stdout: `d_` and three lowercase words joined by hyphens (`d_amber-otter-lantern`); before #1697, `d_` and 16 characters from `A-Z a-z 0-9 _ -`. Read an id as opaque, up to 64 characters from `A-Z a-z 0-9 _ -`. With `--wait`, then what `wait` prints; without it, one line on stderr, either `The answer will come back into this session as a new prompt.` or ``Nothing brings the answer into this session: when only the answer is left, run `starbridge wait <id> --timeout 5m` (again on exit 2).``, then, in a Claude Code session that Claude desktop runs with copies of Starbridge's plugins that have no hooks, one more line starting `Claude desktop runs this session with its own cop` (#1428). In an agent's session, `--session` takes only a session id the environment carries, the agent's own or its parent's (#1748); for another, the decision is posted as the agent's own session, with a warning on stderr starting `starbridge: --session <id> `, which in Claude Code, for an id no Claude Code session on this machine has, goes on `names no Claude Code session` (#1702). With `--answer-in`, one more line on stderr, starting ``When the page's message brings the pick, run `starbridge settle <id>`, then act.`` |
| `wait [<id>]` | Flags `--timeout`, `--json`. Prints `Answer to <id> (<question>): <choice or text>`, or for an `--answer-in` question the owner marked Done, `Answer to <id> (<question>): answered on its page; read the answer there`; with `--json`, the answer as one JSON object with `decisionId` and `choice`, `text` or `done: true`. Exits 2 when `--timeout` passed, saying on stderr `No answer to <id> (<question>) yet.`. With an id that closed already, exits 1 and says how and when on stderr: `starbridge: <id> (<question>) was withdrawn at 13:02: <reason>: no answer will come`, or `was answered elsewhere at 13:02`. With an id, when the owner snoozed the question, prints `Snoozed <id> (<question>) until <time>: no answer before then.` once per snooze and exits 3; with `--json`, `{"decisionId", "snoozedUntil"}`. An agent restart does not end it: it asks the new agent, and after 30 s with none it waits at the server. |
| `waiting <id>`, `working <id>` | Nothing on stdout on success, but `waiting` prints the `Snoozed` line above while the owner has snoozed the question, and the `Answer to` line when the answer came in and no `wait` printed it nor the mod confirmed it (#1484), which it then marks printed. Otherwise one line on stderr, `Marked <id> (<question>) waiting.` (`working`). On a card closed already, exits 1 and says how and when: `starbridge: <id> (<question>) was already answered at 13:02: <answer>`, or `was already withdrawn at 13:02: <reason>`. |
| `settle <id>` | Flags `--outcome elsewhere\|withdrawn`, `--reason <text>`. A withdrawal, the default for a decision without `--answer-in`, requires `--reason`: one line of at most 120 characters, which History shows; without it, or longer, it exits 1 and settles nothing. `--reason` with `elsewhere` exits 1. On success, one line on stderr: `Settled <id> (<question>): withdrawn at 13:02: <reason>`. On a card closed already, it settles nothing, exits 0 and says how on stderr: `starbridge: <id> (<question>) was already withdrawn at 13:02: <reason>` (`answered at 13:02: <answer>` for one the owner answered). When an answer came first, it settles nothing, prints the answer on stdout as `wait` does when no session took it yet, says so on stderr and exits 0 (#1575). |
| `settle --session <id>`, `settle --all` | Every open decision of that session, or of this machine (`--all` asks first, with the count, and needs a terminal: `--yes` skips the question, not the terminal, and `--all` exits 1 without one, #1761). Flags `--outcome`, `--reason` (optional, with `--outcome withdrawn`). Prints `Settled <n> decisions.` (`Settled 1 decision.` for one), or `No open decision session <id> asked.` (`this machine asked` with `--all`) when there is none; exits 1 when the question is declined, 130 on Ctrl-C. |
| `answers --session <id>` | Flags `--wait <seconds>`, `--ack <ack>`. With `--ack`, prints `{"acked": [...]}`: the acks it confirmed now, leaving out any a `wait` or `waiting` printed first (#1484). Otherwise prints one JSON object per line: `{"decisionId", "ack", "line", "waiting", "subagent"?}`, where `line` is the `Answer to` line above, `waiting` is true when the decision is marked waiting (#1484), and `subagent` names the Claude Code subagent that asked (#1702). |
| `answers --all` | Flags `--follow`, `--since <time or duration>` (a duration takes its unit: `90s`, `2h`). Prints one JSON object per line, oldest first, answers to decisions settled since included: `{"decisionId", "question", "choice" or "text" or "done": true, "answeredAt", "session"?, "sessionTitle"?, "project"?}`. With `--follow`, then each new answer until interrupted. Marks nothing seen or waiting. |
| `decisions --open` | Prints one JSON object per line, oldest first: `{"decisionId", "question", "options", "askedAt", "waiting", "session"?, "sessionTitle"?, "project"?}`. |
| `run` | Flags `--title`, `--reason`, then `--` and the command. Exits with the command's code: 127 when it cannot start, 128 plus the signal when a signal ends it. In Codex's sandbox (`CODEX_SANDBOX_NETWORK_DISABLED=1`) it starts nothing, says to run it again outside the sandbox, and exits 1. |
| `hook permission` | Flags `--agent claude-code\|codex\|pi\|opencode\|antigravity`, `--wait`. Reads the hook's JSON on stdin and prints the output its harness defines, or nothing to leave the prompt to the keyboard. SIGTERM means the keyboard answered. For Codex, nothing also when the owner is at this machine. On Claude Code's `AskUserQuestion`, prints the devices' answers as the picker's. Exits 0. |
| `hook settle` | Flag `--agent claude-code\|codex`. Reads the hook's JSON on stdin. Exits 0. |
| `hook question` | Flag `--agent opencode\|pi\|antigravity\|codex`. Reads the hook's JSON on stdin. For opencode, Pi and Antigravity, prints `{"answers": [[label], ...]}` once every question has a device's answer, or nothing. For Codex, on `PreToolUse` for `request_user_input`, starts the race in a detached process (`--race`) and prints nothing. Exits 0. |
| `hook session` | Flag `--agent cursor`. Reads a Cursor `sessionStart`, `stop` or `sessionEnd` hook's JSON on stdin. On `stop` with a question of the conversation open, holds up to 10 minutes and prints `{"followup_message": <answer lines>}`, or at the cap the `wait` line for each question still open, at most 3 times for a conversation with no answer between, then nothing; otherwise prints nothing. Exits 0. |
| `hook ask-user` | Deprecated (#848), for plugins before #1625: prints nothing, which lets the question through to the picker that `hook permission` races. Exits 0. |
| `hello` | No flags. In an Antigravity session, hands the local agent the session's route; prints one line, exit 0, or exit 1 when no agent took it. Outside one, prints that there is nothing to do. |
| `hook pre-invocation` | Flag `--agent antigravity`. Reads Antigravity's `PreInvocation` JSON on stdin; prints `{"injectSteps":[{"ephemeralMessage":…}]}` asking for `starbridge hello` while permission prompts are on and the conversation has not registered, else `{}`. Exits 0. |
| `hook stop` | Flag `--agent antigravity`. Reads Antigravity's `Stop` JSON on stdin; prints `{"decision":"continue","reason":<answer lines>}` when answers to the conversation's questions came in, holding up to 10 minutes while one asked without a route to its language server is marked waiting; else nothing. Exits 0. |
| `hook pre-tool` | Flag `--agent antigravity`. Reads Antigravity's `PreToolUse` JSON on stdin; prints `{"decision":"allow","overwrite":{"BypassSandbox":true}}` when `toolCall` is a `run_command` whose `CommandLine` is one `starbridge ask`, `waiting`, `working`, `wait`, `settle` or `hello` command alone and passes `ask` no `--context-file`, `--input` or `--image`, `{"decision":"force_ask",…}` for a line that does (the file would be read outside the sandbox) and for any other line that names `starbridge` once quotes and backslashes are removed (`LD_PRELOAD=… starbridge ask`, `"starbridge" ask`), `{"decision":"deny",…}` asking for `starbridge hello` for the first other command of a conversation that needs it (see `hook pre-invocation`), else nothing. Exits 0. |
| `pair` | Prints `Pairing code: <code>` first. Once approved, unless the Starbridge app checked it from the QR code, prints `Check code: <code>` and waits for Enter (yes) or `n` on the terminal or for `pair --confirm` or `pair --reject`. |

Codex sessions receive ``Starbridge has the owner's answer to <id>: run `starbridge wait <id>` to read it.``, or for several answers at once ``Starbridge has the owner's answers to <id>, <id>: run `starbridge wait <id>` for each, in this order, to read them.``
(#1597), as a queued prompt. The plugins set `STARBRIDGE_PI_ANSWERS`, `STARBRIDGE_OPENCODE_SESSION`,
`STARBRIDGE_OPENCODE_TITLE` and `STARBRIDGE_OPENCODE_ANSWERS` for the commands their agents run,
and read `STARBRIDGE_CONFIG_DIR`, `STARBRIDGE_AGENT_SOCKET` and `STARBRIDGE_NO_AGENT`. The Claude Code mod sets `STARBRIDGE_CLAUDE_AGENT`, the subagent's agent id, for a subagent's command that runs `starbridge ask` (#1702).

The hooks exit 1 only when stdin cannot be read. Every other command exits 0 on success and 1 on an error, with the error on stderr after
`starbridge: `. Ctrl-C exits 130.
